# An 的 Apple Container 执行引擎

## 目标与职责

让无头 agent 可以提交工作、观察结果、处理授权和重试。一次执行要能回答三个问题：哪个实例持有这次工作，宿主能否确认它已经停止，哪些文件具备交付资格。具体工具、命令和交付质量标准由 spool 与任务定义。图决定哪个节点就绪，引擎负责在指定实例上执行和核实物理状态。

```text
CLI / MCP / Studio
      │
      ├── 直接 run ──────────────────┐
      └── 图提交 → 节点就绪、绑定输入 ─┤
                                    ↓
       instances：任务锁、授权、实例归属、运行租约、版本提交
                  ↕                         ↓
           SQLite 持久化意图       engine：观察身份、执行、确认停止与删除
                                            ↓
                                     Apple Container CLI
```

代码入口为 [实例与运行](../src/instances.rs)、[生命周期判定](../src/engine/mod.rs)、[Apple 命令适配](../src/engine/apple.rs) 和[镜像准入](../src/runtime.rs)。命令行和图共用现有 task、instance、run 与 revision 标识。宿主持有数据库和任务锁，worker 持有运行租约。镜像准入也使用同一个 Apple 后端创建、检查和导出探测容器。

## 执行边界

- agent 在已准入镜像里选择命令，可启动子进程。宿主按 argv 传参。容器以禁网、只读根文件系统启动，挂载限定为实例自己的 input、output、work。input 只读，output 可写，work 的可写性由任务的编辑模式决定。只读工作副本允许并行实例，可编辑工作副本沿用实例层的串行约束。
- 宿主向输入目录提供经过授权的版本。模型调用与跨 spool 交接通过 An 的授权入口进行。创建和执行命令均不向 guest 传递宿主环境变量或模型凭据。驱动专用实例仍由原图尝试独占。
- 宿主保存运行状态、退出信息与命令输出日志。日志可能含输入内容，属于受权限控制的证据。产物、可编辑工作副本和日志是不同的出容器路径；宏 UI 展示的事件应限于用户指令、决定、控制、失败与交付。
- 用户停止任务时先记录意图。运行状态未知、身份不符、停止未确认时，保留待清理状态。再次读取或清理时依据实际库存调和。对同名实例执行停止或删除前检查实例标签和镜像摘要。

## 如何确认完成

| 场景 | 处理与验收依据 |
| --- | --- |
| 正常运行 | worker 记录退出码，确认 guest 停止并重启实例。成功后只读取声明的输出路径，检查文件存在及规范路径，把候选版本和 run 状态一起提交。 |
| 交付 | 有输出的直接 run 进入 awaiting_publication。发布、交接、导出继续经过相应授权。图由 delivery 节点绑定版本。业务验收读取交付文件，例如验证文本字节或检查图像内容。 |
| worker 消失 | 租约释放且账本仍为 running 时，将运行标记为 unknown。不得从租约消失推断命令成功，也不得自动重放命令。 |
| 运行中容器消失 | worker 无法确认命令结果时记录 unknown 并请求停止。控制端仍可用原 run ID 调用 cancel，即使实例已经清空 active。宿主确认容器停止或缺席后结算取消，保留原错误。 |
| 停止或卸载 | 每次操作后重新观察。停止得到静止或缺席证据后才能结算取消；卸载需要容器缺席且实例目录清理成功。操作返回错误但目标状态已实现时，以重新观察的结果为准。 |
| 库存不可读或身份冲突 | 保留错误或观察状态，继续等待可确认的结果。身份冲突的容器不接受破坏性操作。 |

## 验证与后续

运行 `cargo test` 检查授权、恢复与故障路径。清理测试在独立子进程中替换 Apple CLI，覆盖库存不可读、删除失败、身份冲突和恢复。生产二进制使用固定的 Apple CLI 路径。

参考机可用 `python3 examples/composition/relay.py --out <新目录>` 从图入口检验真实的分支交付、版本来源和实例回收。用 `python3 tests/apple_permission_smoke.py <本地镜像>` 从直接运行入口检查两轮授权、发布与导出字节。两项检查均可无头运行。

## 跨任务执行容量

同一个 `AN_HOME` 下，`max_concurrent_runs` 控制可同时执行 guest 命令的 run 数，默认 4，可在宿主的 `config.json` 覆盖。该限制作用于直接运行和图运行。镜像准入、已加载实例数量、排队 worker 数及宿主模型调用有各自的生命周期。

授权通过后，提交事务同时登记 run、实例归属和队列票号。worker 按提交顺序竞争可用槽；有多个空位时队首相应数量的 worker 可同时启动。等待期间释放任务锁，控制端仍可取消。启动前重新检查实例归属及原有输入授权。执行或停止结果尚待确认时保留占用；确认终止或卸载后回收。若排队 worker 意外退出，后续 worker 可以通过租约识别并跳过该票；已取得槽的 worker 失联则须通过原有停止或卸载路径确认清理。

通过 `an status --task <task> <run>` 或 MCP 的 `an_status` 查询自己的运行。为兼容现有轮询客户端，排队仍显示 `status: running`，同时带有 `waiting: {"reason":"execution_capacity","position":1}`；1 表示排在首位。查询仅提供队列位置。使用 `python3 tests/apple_capacity_smoke.py <本地镜像>` 验证三个任务争用一个槽、前项取消后接续和最终清理。

## 已加载实例容量

`max_loaded_instances` 默认 8，按 `AN_HOME` 统计任务实例。普通实例、空闲实例、图的专用驱动实例均占用一个名额。新实例在启动容器前，通过同一 SQLite 写事务检查上限并写入 loading 记录。复用已有实例不再占用名额。已停止、状态未知和清理中的实例继续占用名额，直到成功卸载。降低上限后，已有任务可以继续执行，新增实例等待容量释放。独立的镜像准入探测容器和 An 以外启动的容器不计入此值。

直接调用 `load` 满额时返回可重试错误。图节点保持 `queued`，在 `graph state` 的 activity 中返回 `waiting_reason.reason = instance_capacity` 和当前上限。持有方卸载实例或结束任务后，下一次图调度会重试同一次尝试。宿主保留空闲实例供复用；如一个任务已占满容量，又需要加载另一种 spool，可通过 CLI 或 MCP 卸载已用完的实例。实例名额按可用时申请，不提供跨任务 FIFO 保证。

参考机验收命令为 `python3 tests/apple_instance_capacity_smoke.py <composition painting 镜像>`。该测试让两个任务并发申请同一个名额，验证原实例复用、图节点等待原因和卸载后继续执行。

## 每个实例的 CPU 与内存

`config.json` 的 `container_cpus` 和 `container_memory_mib` 分别指定新容器的 CPU 配额（按核计）和内存上限（MiB），默认值为 2 和 1024。普通任务、专用驱动和准入探测使用同一启动路径。宿主在容器启动后读取 Apple Container 的实际分配，核对通过才接受启动；不一致时沿用启动失败的清理流程。通过 `an state --task <task>` 的实例 `resources.cpus` 和 `resources.memory_bytes` 可以查看最近一次观察的分配值。

变更配置在新建实例时生效。复用和重新启动同一个实例会保留其原有分配，需要调整时先卸载再加载。来宾内可从 cgroup v2 的 cpu.max 和 memory.max 核对进程的 CPU 时间配额和内存上限。参考机上 1 核配额对应 cpu.max 的配额与周期相等；虚拟机可以有更多在线处理器。宿主侧总占用还包括虚拟化开销及准入探测。运行因来宾内存不足而退出时，沿用已有的退出状态与日志；单凭退出码无法判定 OOM。

## 实例磁盘、输出与日志

| 设置 | 默认值 | 生效范围 |
| --- | --- | --- |
| `instance_disk_mib` | 512 MiB | 每个新任务实例一个定容稀疏磁盘映像。input、output 和 work 共享容量，文件系统元数据也占空间。 |
| `run_output_bytes` | 32 MiB | 一次运行声明的所有输出文件原始字节之和，加上可编辑模式下需要保存的整份 work 快照。 |
| `run_log_bytes` | 4 MiB | 一次运行 stdout 和 stderr 合并后的日志文件。 |

磁盘写满时来宾写入会收到 ENOSPC；程序可以自行处理该错误。命令失败时，日志保留来宾诊断。磁盘映像在实例目录里按需增长。成功卸载包含删除容器、分离映像和清理目录；分离失败保留 cleanup_pending，供后续重试。旧版创建的实例可继续清理，运行新命令前需卸载并重新加载。镜像准入探测、SQLite 历史版本和宿主其他文件有独立的生命周期。

宿主在确认来宾停止后检查产物，在读取和编码每个文件前扣除字节预算。超限时 run 失败，可编辑 work 回到已提交版本。下次运行会清空上一次的 output。日志写入进程有独立的文件大小限制，额外一个字节用于区分刚好达到上限与超限，正常结算时截去该字节并记录失败原因。

参考机可用 `python3 tests/apple_storage_smoke.py <本地镜像>` 验证磁盘写满、累计输出超限、日志超限、同实例恢复和磁盘分离。

## 关闭任务与版本回收

任务关闭且实例卸载完成后，宿主在同一个 SQLite 写事务里检查引用、删除无引用的 revision 文件集并记录结果。其他任务在运行、等待用户或等待清理期间，其引用的版本均予以保留。停止时仍在发送的模型调用先完成结算，再由调度器或再次 finish 触发回收。若事务中断，版本删除和回收记录一起回滚。

已发布的直接运行保留导出和恢复用到的版本。图交付保留合并文件、各个绑定、面板代码，以及 Studio 能沿输入、前置节点、驱动和保存节点追溯的证据。未发布的临时输出可以释放；任务、节点和权限审计记录仍可查到原来的标识。镜像准入的代码版本也保留。新版本和拥有它的记录在同一个事务中登记，防止并发关闭其他任务时收走刚生成的版本。

内部记录 `revision_gc` 以关闭的任务 ID 为键，保存本次全库扫描前后的 revision 序列化字节数以及删除数量。重复 finish 保留首次成功记录。删除释放的页供 SQLite 后续写入复用；数据库文件的物理长度与有效数据量分别计量。可用 `python3 tests/revision_gc_smoke.py <本地镜像>` 检查实际占用、恢复交付并逐字节核对导出结果。

## 故障恢复与并发验收

从仓库根目录构建 `cargo build`，选一个已缓存、含 `/bin/sh`、`sleep` 和 `touch` 的 spool 镜像。以下三项检查使用真实 Apple Container，每次创建独立的临时注册库。

```sh
python3 tests/apple_reliability.py "$image" --mode pressure --seconds 600
python3 tests/apple_reliability.py "$image" --mode worker-loss
python3 tests/apple_reliability.py "$image" --mode guest-loss
```

本轮使用 macOS 27.2.1、Apple Container CLI 1.7.1 和本地 Python 测试镜像。压力测试每个实例分配 1 核、512 MiB 内存和 64 MiB 磁盘，故障测试将整个注册库限制为一个执行槽。

| 验收项 | 参考机结果（2026-11-28） |
| --- | --- |
| 四个任务争用两个执行槽 | 609.19 秒完成 41 轮、164 次运行。按每次执行的起止记录计算，并发峰值为 2。每个候选文件都与其任务和轮次的预期字节一致，每轮结束时执行队列为空。 |
| 执行中终止宿主 worker | guest 写出启动标记后，对该 run 的 worker 发送 SIGKILL。新的 CLI 进程读到 unknown，另一个任务继续排队。取消并确认 guest 停止后，排队任务取得槽并产出预期文件。 |
| 执行中移除容器 | 只强制移除该 run 的实例。worker 记录 unknown，保留已占用的槽直到调和确认实例缺席；在状态查询后再次调用 cancel 仍能结算。 |

两项故障测试都在中断前发布一份文件，在恢复后经过导出授权并核对原始字节，重复取消返回 cancelled，原任务可正常关闭。三项检查均核对测试实例已从 Apple 库存消失、实例目录已清理、执行队列已清空。

### 内存耗尽

使用带 Python 3 的测试镜像，在宿主执行 `python3 tests/apple_reliability.py "$image" --mode oom`。探针先检查来宾的 `memory.max` 确实为 512 MiB，再等待另一个任务排在唯一执行槽的队首。随后子进程尝试写入一块 640 MiB 的内存。探针通过已授权的 run 日志报告执行前后的 `memory.events` 和子进程的退出信号。

参考机上 `oom_kill` 从 0 增至 1，子进程收到 SIGKILL，探针返回 137。An 记录 run 为 failed，未产生候选版本。排队任务完成后，原实例也成功执行了新的命令，两份产物均通过字节比对。这里的 OOM 归因依赖受控探针取得的内核计数。普通 spool 的退出码和自报日志不能单独作为宿主判定 OOM 的依据。

### 多小时混合负载

用同一个注册库连续执行 `python3 tests/apple_mixed_soak.py "$image" --seconds 7200 > mixed.jsonl`。每轮创建两个任务，等待一条命令在来宾开始执行，取消它，让排队的任务取得槽，随后授权发布、导出并逐字节核对交付。最后关闭两个任务并检查实例目录和执行票据。首轮以及此后约每 15 分钟的一轮还会执行上面的 OOM 验收。

每行 JSON 记录该轮实例加载时及任务关闭后的宿主采样。`registry_allocated_kib` 按实际分配的磁盘块统计，跨挂载点的目录内容不会与稀疏映像重复计数；保留的交付和审计账本占用也在其中。`host_wired_bytes` 和 `host_compressor_bytes` 是 macOS 整机指标，会受同机其他程序影响。最后一行的 `cleanup: confirmed` 表示所有测试实例均已从 Apple 库存移除。

首次长测完成 254 轮后，下一轮的 cancel 在结算时遇到 SQLite 写锁竞争。回归测试让另一个连接占用写入权并登记队列票据，可以复现相同错误。调和逻辑现在在查询待结算的 run 前申请写事务，在同一次提交内记录取消、释放该 run 的槽并更新实例。容器的停止和库存查询在此事务前执行。混合负载失败时会保留隔离注册库以便排查。

修复后在新注册库从零执行的结果（2026-11-28，Apple Container CLI 1.7.1）如下。

| 指标 | 结果 |
| --- | --- |
| 连续工作负载 | 7,217.87 秒，331 轮，686 次 run，662 个任务关闭。 |
| 内存耗尽和交付 | 8 次观察到来宾 OOM 及 OOM kill 计数增加，每次均验证排队接续与同实例复用。331 次发布和导出全部逐字节一致。 |
| 宿主磁盘 | 每轮从实例加载到两个任务关闭，注册库分配空间回落的中位数为 20,488 KiB。注册库从 16 KiB 起步，最后一轮关闭后为 3,172 KiB，包含保留的交付与账本。 |
| 宿主内存 | 331 轮中 196 轮的整机 wired 内存在关闭后下降。整机数据受其他进程影响，不能据此量化单个实例的内存回收量。 |
| 最终清理 | Apple 库存中无测试容器，实例目录全部移除，执行队列为空，测试进程退出码为 0。 |

### 参考 Mac 的整机恢复

正常重启和突然断电各使用一个全新的持久目录。先用 `python3 tests/apple_reboot_acceptance.py prepare "$case_dir" "$image"` 准备一份已发布文件、一个正在执行的 run 和一个排队 run。脚本返回 prepared 后，操作员在 30 分钟内对指定机器执行本轮的中断。机器恢复且 Apple Container 服务可用后，执行 `python3 tests/apple_reboot_acceptance.py verify "$case_dir"`。两轮分别保存中断方式和输出。

verify 先核对 macOS 启动会话已改变，再检查 SQLite 完整性、两个旧 run 的状态和开始记录。随后结算取消，检查容量、映像目录和 Apple 库存，重新授权导出故障前的交付并核对 SHA-256，再启动一个新实例验证接续。准备目录含该轮测试的操作员凭据，verify 成功后会结束授权并删除凭据文件。中止实验可运行 `python3 tests/apple_reboot_acceptance.py cleanup "$case_dir"` 卸载实例并结束授权。

同一台日常使用的 Mac 可以分两次做验收。每次应先保存其他工作，然后在实际中断前准备该轮注册库。内置电池机型拔掉外接电源会切换到电池。若实际采用长按电源键强制关机，报告应写明“强制关机”；启动会话的变化只能验证经历了重新启动，不能证明电源被物理切断。

## 与第一版计划的差距

第一版设计在提交 `8105f66` 中列出了无头运行、资源预算、引用回收和可靠性验收。当前进度如下。

| 第一版范围 | 当前证据与待验项 |
| --- | --- |
| agent 提交、观察、停止；交付可验收 | CLI、MCP 和图共用实例归属和运行账本。直接运行可授权发布和导出，图交付可在新任务中恢复，参考机有文件级验收。 |
| 跨任务容量与排队 | guest 执行使用持久化 FIFO 票号；CLI 和 MCP 可读等待原因。已加载实例另有上限，普通实例、驱动和空闲实例都占名额。 |
| 资源耗尽 | 已实施 CPU、内存、实例磁盘、输出和日志预算。参考机覆盖来宾 cgroup 配额、磁盘写满、输出和日志超限，以及有内核计数支持的 OOM、失败结算、队列接续和实例复用。 |
