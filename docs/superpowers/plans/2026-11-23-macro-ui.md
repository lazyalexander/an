# Macro UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Bridge Studio user a single web page — stage strip, current-output preview, decision bar, collapsed troubleshooting drawer — served by the existing orchestrator, while agent internals stay hidden.

**Architecture:** An additive UI-serving layer inside the orchestrator: an instance manifest (labels/stages) + a pure state-builder that aggregates orchestrator status, the ledger, and the archive lineage into one JSON state; a plain HTML/JS page polls it. Decisions (adopt / re-render / retry / restore) are new orchestrator methods and endpoints; the Krita docker slims to a pure agent (push, heartbeat, preview export, restore pickup). Version lineage lives in the archive sidecars — cumulative, never discarding.

**Tech Stack:** Python 3.10 stdlib only (`http.server`, `zipfile`, `json`); Krita 5.3.4 bundled Python + PyQt5 for the docker; plain HTML/JS, no framework; pytest.

**Spec:** `docs/superpowers/specs/2026-11-23-macro-ui-design.md`

## Global Constraints

- Generic framework: the manifest is the *only* place Bridge-specific labels/stages live; state-builder and page are instance-agnostic.
- Never discard or overwrite user work: archives are never clobbered; re-render/restore create new versions; preview export never saves the user's `.kra`.
- No intent input anywhere in the UI; behavior events are ledger-recorded only.
- No new dependencies (stdlib + PyQt5 already bundled with Krita).
- Krita-bundled Python is 3.10: adapter code must stay 3.10-compatible.
- All HTTP routes new to this milestone (`/ui`, `/static/*`, `/api/macro/*`, `/api/decision/*`) require the per-boot UI token (`?key=` query param or `X-Bridge-Key` header); legacy `/api/pose|lock|unlock|status|session/layers` stay unkeyed (docker/Blender channel).
- Re-render = return to ADJUSTMENT to re-orbit (rendering is deterministic per pose; same-pose re-render is meaningless).
- Tests run from `studio/`: `python3 -m pytest tests/ -q`; existing suite must stay green (39 passed, 3 skipped).

## Review Focus

1. **Krita projection export** — `Document.projection()` behavior on Krita 5.3.4 is unverified; if wrong, no live preview. Pinned by the manual smoke step in Task 8 (reference machine) and by the pure cadence/atomic-write tests; the page must show the last good preview (or placeholder), never a broken image.
2. **Adopt-before-push race** — the user clicks 采用 while the archive `.kra` is not pushed yet; expected: `409 archive not pushed yet`, the button stays enabled, nothing is recorded. Pinned in Tasks 3/4.
3. **Half-written preview reads** — the HTTP layer must never serve a partially written PNG; the docker writes tmp+rename. Pinned in Task 8's atomic-write test, consumed by Task 6.
4. **Ledger growth** — `build_state` runs every poll against a growing `ledger.jsonl`; drawer data must be bounded (last 200 entries) and the state build must not read the file more than once per call. Pinned in Task 5.
5. **Token leakage into docker-less runs** — if `run/ui_token` is missing (orchestrator started without the macro layer), the docker must keep pushing and skip heartbeat/restore quietly. Pinned in Task 8.

### Task 3: Orchestrator decisions (adopt / re-render / retry / restore)

**Files:**
- Modify: `studio/orchestrator/app.py`
- Test: `studio/tests/test_app.py`

**Interfaces:**
- Consumes: Task 1's `set_version_status`, `list_versions`.
- Produces (all on `Orchestrator`, guard-protected, raise `InvalidTransition` with a readable message on bad state):
  - `__init__(..., archives_dir: Path | None = None)` — new optional kwarg (default `run_dir / "archives"`).
  - `adopt() -> None` — requires LOCKED + session.state `"rendered"`; the archive `pose_{session.id}.kra` must exist (else `InvalidTransition("archive not pushed yet")`). Sets sidecar status `adopted`; records ledger `decision` with `decision="adopt"`, `session`, `latency_ms` = now − render-done time (track `_render_done_ts` set in `_render`).
  - `rerender() -> None` — requires LOCKED; if the archive exists, sets status `superseded`; records `decision` `re-render` (with latency if render had finished, and `lock_duration_ms` from `_lock_ts` — also add `lock_duration_ms` to the existing `unlock` ledger record); then phase ADJUSTMENT, session/layers cleared (same clearing as `unlock`, but ledger kind is the decision, not `unlock`).
  - `retry() -> None` — requires LOCKED + session.state `"failed"`; sets state back to `"rendering"`, spawns the render thread again (same session), records ledger `render_retry`.
  - `restore(version_id: str) -> dict` — requires the version to exist in `list_versions(archives_dir)`; copies `.kra`+sidecar to new id `{version_id}--restore-{YYYYmmdd-HHMMSS}` (new files, `shutil.copy2`), sets the copy's sidecar `status="pushed", restored_from=version_id`; stores `self._pending_restore = {"id": new_id, "kra": str(path)}`; records ledger `decision` `restore`. Returns the pending dict.
  - `pending_restore` property -> `dict | None`; `ack_restore() -> None` clears it.
  - `note_heartbeat() -> None` / `heartbeat_age_ms() -> int | None` — last-heartbeat tracking; ms since the last heartbeat, `None` when no heartbeat has ever arrived (callers compare against 3000 ms).
