# 产物流设计（五）——Spool、Instance、Container 与 Run

主 agent 委托 subagent「核对纪要里三项决定的出处」。报告交回后，主 agent 又问「把你查过的两段原文并排列出来」。harness 可以唤回原来的 subagent，也可以另派一位。两种情况下，An 都应能按当前授权提供原来的材料版本，把补充报告关联到同一项委托。原容器可以在两次请求之间回收。

## 四个执行对象

| 对象 | 它标识什么 | 哪些状态随它保留 |
| --- | --- | --- |
| **Spool** | 经 An 准入、按摘要固定的能力镜像。清单描述接口，包内说明供 agent 选择命令和输入。确定性的排版程序也可以是一个 spool。 | 准入记录固定镜像、平台和声明。任务内获准编辑并提交的程序另有工作副本版本，可和原镜像一起定位。 |
| **Instance** | An 为某个 task 加载指定 spool 后管理的一份隔离工作副本。 | 实例 ID、所属任务、spool 和当前占用记录由宿主维护。同一实例可以先后承载多次 run。只读工作副本可用不同实例并行试验，对同一可编辑工作副本的写入串行执行。 |
| **Container** | Apple Container 提供的隔离执行环境。An 启动禁网容器，按授权挂载输入，并按实例归属观察、停止和清理容器。 | 进程和内存随容器停止而结束。需要供后续工作使用的文件，按任务约定保存为输入、输出或工作副本快照。 |
| **Run** | 一次具体的命令执行请求，记录它是否启动、怎样结束、生成了什么。 | run ID 关联任务、实例、spool、入口参数、输入版本，以及实际观察到的退出结果、输出版本和日志。图内执行还关联节点和本次尝试。显式重试产生新的尝试，前次证据保留原归属。 |

主 agent 或获准的 subagent 选择 spool、命令、输入和期望输出。An 核对权限，选择兼容的实例并调度容器。直接调用也可指定已有实例，宿主仍要核对任务、spool 和占用状态。容器内的程序可以启动子进程、自由试算。An 记录它观察到的入口和结果，需要用于核验的中间步骤可由 spool 输出为证据。跨容器交接、宿主模型调用和下游 MCP 调用经 An 执行。[镜像准入与接口](spool-images.md) · [Apple Container 执行边界](container-engine.zh-CN.md)

## 谁委派 subagent，谁为结果署名

harness 管理主 agent 与 subagent 的会话、记忆、分工，以及追问时恢复哪个线程。An 可以在任务收到新指令时通知已配置的 harness，随后按照请求提供获准的材料和执行能力。一次审阅委托可以使用多次 run。若隔离驱动还需要模型，它可以提出模型节点。An 在宿主执行已获准的调用，保留调用回执，再按授权把结果版本交给接续步骤。主 agent 也可直接运行纯排版程序。

一项委派首次经 An 请求执行或交回产物时，关联任务内能唯一定位它的记录，例如发起这项审阅的指令事件。后续提交关联同一委托和实际请求者，追问时再指定先前报告的版本。这样，同一线程处理两项审阅也能分清每个 run 服务于哪一项。

An 从可信绑定取得调用主体，根据输入绑定、run 和交接回执记录材料流向。harness 可附上不透明的执行者标识以便回查协作经过，该标识只用于关联。若由已认证的主 agent 代交，记录应注明主 agent 提交、harness 报告哪位 subagent 参与。主 agent 能转授哪些材料、报告可以交给谁，见[身份、授权与权限传递](material-permissions.zh-CN.md)。

例如，subagent 找到两段原文，主 agent 据此决定退回纪要，报告作者和决策者分别署名。如果 subagent 自己具有可验证的退回委托并作出决定，就把它登记为决策者，关联当时有效的委托。主 agent 转达时保留这条归属。[决定与验收的职责](decision-authority.zh-CN.md)

## 原实例回收后怎样接着查

1. **第一次核对。** An 把获准的纪要版本和来源块交给定位段落的 run。整理报告的 run 使用冻结的定位结果。报告引用两段原文及对应的执行证据，以待审材料交回主 agent。试写的脚本、草稿和日志按原任务的范围留存。[主 agent 的工作区](workspace-lifecycle.zh-CN.md)
2. **保留继续工作所需的版本。** 原委托关联受检材料、spool 摘要、实际用过且后续需要的工作副本、报告版本及证据引用。在委托仍可接续或报告仍引用这些材料期间，An 保留对应快照。等待追问、模型结果或人的决定可以释放容器。
3. **接到追问。** harness 选择执行者，提交原委托引用、待补证的报告版本和本次所需材料。An 按当前主体和授权核对这些版本及可见工作文件，再复用空闲实例或加载新实例。若旧副本混有本轮范围外的材料，可用同一版 spool 和满足本次委托的获准快照重建。若核查恰好需要受限的旧副本，则等待该版本的授权。
4. **交回补充结果。** 新 run 使用自己的 ID。补充报告作为新产物交回，指回原报告版本、委托和这次实际采用的原文块。若已获修订权，也可以提交原报告的新版本。主 agent 能分别查到两次工作的执行路径。若缺少必要版本或本轮读取权，记录尚未完成的检查，并向有权主体说明需要补充哪项输入或授权。

宿主重启后，先按已记录的尝试核对状态。同一任务中按原幂等键重提相同的图提交，返回原回执。若上次命令的结束状态无法确认，保留「结果未知」，确认终止并结清旧尝试后才能显式重试。追问则是一项有新请求标识的工作。新执行者可以对同一材料给出不同判断，各份报告分别保留署名和依据。

## 现有基础与首版验收

仓库已有按摘要准入的 spool、任务绑定的实例、专用驱动实例归属，以及 run 的输入、argv、工作副本和候选输出记录。图调度器关联节点尝试与执行证据。控制器已有与 harness 无关的唤醒入口，示例适配器自行保存会话标识。第五项要补齐的是从原委托、执行者归属和报告版本定位后续尝试，并验证更换执行者、回收实例后的接续行为。[实例与 run](../src/instances.rs) · [图调度与证据](../src/graph/scheduler.rs) · [控制器唤醒入口](../studio/an_host/runner.py) · [示例会话适配器](../examples/markdown_review/codex_session.py)

| 无头验收场景 | 预期结果 |
| --- | --- |
| 一个审阅委托使用定位和排版两次 run，再交回一份报告 | 两条执行记录各有输入版本、argv、spool、实例和结果。工作台收到一份待审报告，能从它追到两次执行。单独运行排版 spool 也能产生有效的 run 记录。 |
| 首次交回后卸载实例，将同名镜像标签指向新版，再分别让原 subagent 和新 subagent 补证 | 两条路径都以原准入摘要和指定工作副本加载新实例，打开相同的原文版本，以新的执行记录交回两段文字。新报告指向原委托，原报告仍可原样打开。 |
| 在容量充足时并行运行两个只读副本试验，再尝试借用另一任务或驱动专用的实例 | 两次执行的时间区间重叠，实例 ID 不同，声明输出只含各自的标记。越界的请求在执行前被拒绝。 |
| 上次实例或工作快照含有内部备注，本轮只准核对两段公开原文 | 检查 An 实际提供的输入和工作目录，里面只有获准材料。提交旧实例 ID 或同一个执行者标识，权限仍按本轮核对。 |
| 在结果已提交和执行结果未知两个时点重启，随后查询或重试 | 已完成尝试返回原结果。未知尝试保留原记录，确认终止并显式重试后可查到新的 run，两次结果可分别追溯。 |
| 分别由主 agent 采纳建议、由获授权的 subagent 直接退回纪要 | 第一例的决策者是主 agent，第二例能定位 subagent 及有效委托。两个决定均可查到请求提交者、报告版本和实际交接回执。 |
