# 产物流设计（一）——决定的来源与影响

从交付文档里点开一句「图书馆周一开馆」，应当能查到这句话引用了哪一版决定、是谁决定的、当时看到了什么。反过来，从这版决定出发，也应当能找出哪些文档已经采用它，改成「周二开馆」后哪些地方需要复核。

管理产物流是 An 的后端核心。An 记录自己经手的版本、授权、执行和交接，并验证这些记录之间的引用。人或受托 agent 作业务决定，验收者检查产物是否符合要求。验收结论也有署名、依据和所验的版本。

## 一版决定需要留下什么

决定一经提出就取得独立的产物 ID 和首个不可变版本。采用或拒绝某一版时，An 记录作出选择的主体和事件。修改结论或依据时，在同一产物下创建新版本，指向被修订的版本。纪要、公告、行动清单可以各自修订，并持续引用当时采用的那一版决定。

| 要回答的问题 | An 需要保存的记录 |
| --- | --- |
| 谁决定，谁代为执行？ | 分别记录提出者、作出或采纳决定的主体、执行者。受托 agent 作决定时，关联授予者、适用范围和当时有效的授权记录。宿主验证的调用身份与 harness 报告的 subagent 身份分别保存。 |
| 怎样得出结论？ | 决定内容、决定者提交的理由、采用的选项以及明确引用的材料版本和块。按规则自动处理时，记录所用规则版本。若只记录了选择，理由标为「未提供」。批准数据流动另记为权限事件。 |
| 经过哪些 spool，实际用了什么？ | 对每次执行记录任务、节点、尝试 ID、spool 镜像摘要、入口命令和参数（argv）、各输入端口绑定的版本、输出版本与退出结果。可编辑代码关联当时的工作副本版本。经 An 调用模型时，关联该次调用及其输入、输出和已记录的用量。 |
| 哪些证据可复查？ | 每次尝试关联已留存的中间文件、日志片段或验收报告。被引用的日志片段冻结为快照，标明所属尝试、字节范围与截断情况。涉及私有内容的参数、理由及证据正文沿用其读取权限，授权记录只引用标识与范围。 |
| 作决定时的图是什么样？ | 记录任务、决定者所见的图修订与事件游标，以及 An 接受决定时的时间、修订与游标。修订确定当时已有的节点和边，游标确定当时已发生的等待、响应、执行与交接。 |

## 让引用跟着文档流转

每条块引用记录使用方、来源以及引用或改写等关系。两端各自指定**产物 ID、不可变版本、块 ID**。例如，公告第一段引用决定的结论块，决定的依据块引用纪要中的议程项。spool 在交回文档版本时一并交回引用。An 检查两端存在、来源属于该次获准使用的材料，再把文档版本与引用一起提交。同一条引用可按任一端点查询，业务含义由产生者声明，可由验收者复核。

块在同一文档内移动时可以保留 ID。拆分或合并产生新块，并列出其来源。已经发布的引用继续指向原版本。新文档的块清单要逐项说明来源，可以是有署名的原始陈述（如人的直接选择），也可以引用已有块。An 在提交时指出缺项或无法解析的端点，验收者检查实际采用的材料是否列全。对于只有文件绑定的旧交付或格式，查询保留文件版本，显示「来源精度为文件」。

**内容引用**回答「这句话依据什么」，**执行和交接记录**回答「哪次运行取得了哪些版本」。节点间的先后依赖用于还原流程顺序。即使同一个 spool 收到两份文件，要把某段结论归给其中一份，仍需该段的来源引用。

同一块如何出现在多份文档里，以及其中一份怎样单独采用修订版，见[产物的独立修订与跨文档块引用](artifact-revisions.zh-CN.md)。

## 在动态图中固定当时的事实

An 在决定触发后续工作前，把决定版本、归属、来源引用和图位置一起提交。由该决定触发的图变更回指这版决定。每次改图保留节点和边的变更，每次执行状态变化记录对应的尝试和输入绑定。两者按事件游标排序，足以还原任一已记录时刻的图。后来追加的分支只在追加后的图上可见，后一次重试成功也保留前一次失败的历史。

执行与交接以 An 实际观察到的结果入账。对可能产生外部效果的操作，先持久化目标、版本和请求标识再调用，收到回执后追加结果。宿主在发送后失去回执时标为「结果未知」。恢复时按原请求核对，已确认的操作返回原回执。未知操作的再次执行需要显式重试，并产生新的尝试记录。

## 向上查依据，向下查影响

- **从交付块回查。** 沿固定版本的块引用找到决定与原始材料，沿实际绑定找到执行尝试、相应 spool 和证据。每一跳给出关系和依据。agent 提交的理由显示为该主体的陈述，宿主观察到的执行显示为执行事实。
- **从决定版本正查。** 列出它触发的图变更，以及直接引用它的文档块，再沿引用找间接派生的块、相应交付及工作区。只有文件级证据的下游单列为「可能受影响」，并给出文件绑定。修订决定后，可据此复核旧交付，业务后果的预测标注判断者和依据。
- **查询扩散范围。** 用回执区分「获准交接」「已交给指定 spool」「已在工作区发布」「已导出到指定目的地」。若要回答外部接收方是否收到或采取行动，还需该接收方的回执。结果给出截至哪个事件可证实哪一步。

主 agent 的 workspace 接收明确交给它的材料。一次图运行中采集的私有中间文件与日志留在该次运行的只读证据视图。核对时，subagent 可以按授权读取指定快照，验收报告成为新的产物。Studio 和任务范围内的 MCP 共用查询规则。查流向与读原文分别校验权限，结果只包含调用方可见的节点、关系和目标。关闭任务并回收中间产物时，仍被交付、决定或活动图引用的版本、图历史和证据必须保留。

## 首版如何验收

已有的会议纪要实验把公开条目从整理 spool 交给排版 spool，生成公告。图提交已有修订和幂等回执，run 已有输入绑定与尝试证据，交付已有冻结版本和按权限查询上游节点的入口。首版要补齐的是独立的决定版本、跨文档块引用、按当时位置还原动态图，以及按决定版本反查去向。[会议纪要实验](../examples/minutes/demo.py) · [图提交](../src/graph.rs) · [执行与交付](../src/graph/scheduler.rs) · [来源与证据读取](../src/graph/sources.rs)

以会议纪要实验为基础，首版应通过以下无头验收。

1. 整理 spool 根据纪要提出「周一开馆」，人采纳这一版。公告和行动清单分别引用它。给定公告中的句子，查询能返回决定者、提议来源、纪要块、整理和排版两次执行的镜像与实际入参，以及获准读取的日志。若把来源改为不存在的块，An 应指出失效的引用，整份新版本提交失败。
2. 人看到提案时，图显示「待决定」和当时的输入。按采纳回执的游标查，提案已被采纳。接续驱动随后追加的排版节点只出现在第三个时点。重启前后，同一游标得到同一视图，采纳回执保持同一标识。
3. 在同一工作区的另一个任务中，让获得委托的 agent 把开馆日修订为周二。记录能指回它的授权。反查周一版准确列出公告和行动清单中引用开馆日的块，排除有独立来源的「免费登记」。旧公告仍显示周一，明确采用新版的文档显示周二。
4. 给 subagent 只读权限核对一份运行证据。它能读到指定版本，写入被拒绝，其他私有日志及其目标不可见。关闭原任务并执行回收后，从交付仍能定位到引用的证据，重新获准后能读回相同内容。
5. 分别制造已授权但未交接、成功发布、导出结果未知三种结果。正向查询只将有对应回执的事实标为已发生。重新打开查询或恢复宿主时，未知的导出不会再次执行。
