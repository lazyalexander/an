# 产物流设计（四）——主 agent 的 Workspace

打开「产品发布」工作区，应该能接着处理昨天交回的纪要，看到哪些决定已生效、哪些提议待审、哪些交付因上游修订需要复核。即使原来的聊天已经关闭，这些材料仍有同一个身份和版本。

**Workspace 是一组工作的长期归属和共享边界。** 一份材料首次在任务内提交时就可以归属该 workspace，并暂时只在任务内可见。明确交给主 agent 的草稿可以立即出现在工作台上。容器内已经排版完成但尚未交回的 PDF，仍属于该次运行的内部材料。

## 四个对象分别管什么

| 对象 | 持有什么 | 换上下文时怎样处理 |
| --- | --- | --- |
| **Workspace（工作区）** | 共享产物及其版本、交给主 agent 的材料、决定与交付记录，以及工作区的流向策略和长期委托。 | 可以跨会话、任务和 harness 延续。读取某份材料或代表工作区行动时，还要核对调用方的权限。 |
| **Session（会话）** | harness 管理对话、上下文和 subagent 线程。An 保存会话与工作区的绑定，以及本次获准操作的任务。 | 两个会话可以独立工作。会话标识用于定位和重连。换会话接续同一任务时，重新核对身份、任务关联和操作权限。 |
| **Task（任务）** | 一次具体委托的目标、执行图、私有候选、运行证据，以及交回哪些版本。工作区内的 task 直接归属 workspace。 | 同一未关闭任务可以跨 turn 接续。关闭聊天保留任务。基于历史图交付开展新工作时，创建新任务并引用原交付。 |
| **Turn（操作轮次）** | 某个任务内当前有效、可撤销的操作授权，以及实际使用的策略和委托版本。 | 结束或更换 turn 后，新动作按新轮次的凭据和授权核对。旧轮次的一次性许可失效，已提交的决定、收件和执行回执继续保留。 |

一个 workspace 在同一时刻由**一个主 agent** 对用户负责。切换会话可以继续由同一个主 agent 工作，它也可以并行推进多项任务。harness 安排 subagent 的分工、记忆和唤回。若用户更换主 agent，An 记录接管，按新主体或角色核对委托，并结束旧主体代表该工作区发起新动作的权限。已开始的运行继续按原尝试核对结果。谁作过决定，始终按当时的主体署名。

## 一份材料怎样进入工作台

设容器中的 agent 从会议记录第七段提取出「建议周五上线」，在授权范围内试写了三份草案。它可以自由选择容器内的命令和试算方法。An 在材料进入容器、调用宿主能力和结果离开容器时检查相应的权限。回查时可读取实际留存的版本和日志，捕获范围随证据保存。

1. **提交材料。** agent 在任务内把这条提议及其来源块存成一个确定版本。若三份试稿也被留存，它们归入运行的私有证据。An 根据生产者明确提交的对象登记决定。
2. **定向交回。** 发送方选定产物版本或块、接收方「本工作区的主 agent」和用途，例如「请审阅」。An 核对授权，在同一事务中保存收件及其回执。回执关联提交者、来源任务与节点尝试或人工提交事件、版本引用、接收方、用途和授权依据。此后工作台显示「待审」。主 agent 离线也能完成交接。同一幂等键与相同参数返回原回执，同键更换版本会报冲突。
3. **处理收件。** 主 agent 可以采用、退回或要求补证。处理结果指向原收件和具体版本。「已采用这份草稿」记录审阅结果。「已决定周五上线」另需有权限的主体拍板并署名。新版材料通过新的交接进入工作台，原收件仍指向旧版。[决定与验收的职责](decision-authority.zh-CN.md) · [产物与块的版本](artifact-revisions.zh-CN.md)
4. **发布或导出。** 向工作区正式发布、把内容交给另一任务或导出给客户，均按实际版本、接收方和流向核对，并留相应回执。「请审阅」的交接只覆盖所选用途。已经具有发布授权的任务也可直接交付，工作台按实际回执显示为「已发布」。

宏 UI 与无头客户端按当前身份列出待审材料、已共享的决定、交付和待复核的引用。另一会话获准代表同一主 agent 工作时可以取回这些收件。其他任务的私有候选及日志受原范围约束，列表、搜索和来源查询也只呈现调用方可发现的对象。接收方能打开一条决定时，读取其所引原始会议记录仍需有效的读取授权。跨工作区交接还要记录获准的目的工作区。

## subagent 怎样只读核对一次图运行

一次图运行可以在原工作区中作为**只读执行快照**打开。快照归属原任务，固定图修订、事件截止游标、节点尝试及材料版本。它可以包含获准的输入、输出、代码或日志片段。图继续扩展或节点重试后，原快照仍然定位到核查时的内容。日志片段引用当时冻结的字节范围。[决定发生时的图与证据](artifact-flow.zh-CN.md)

例如，审阅 subagent 只获准核对「第七段是否支持周五上线」。An 可以只交给它第七段的冻结内容和待核结论，报告以新产物交回主 agent 并引用所核对的块。即使快照中另有私有录音，这次授权也只提供选定材料。若实际挂载了整份获准快照，An 能证明整份快照交给了该执行者。报告引用第七段是另一条记录，逐文件阅读情况以实际观测为准。

运行结束并清理容器后，仍被工作台收件、保留的决定、交付、活动图或仍在使用的快照引用的证据须保留。只留存一个日志片段即可满足该引用时，可以独立保留片段及其来源。无引用的临时版本按任务回收策略清理。保留数据与允许读取分别判断。

主 agent 后续要求补证时，harness 可以唤回原 subagent 或另派执行者。重开实例所需的版本以及新结果与原委托的关联，见 [Spool、Instance、Container 与 Run](spool-execution.zh-CN.md)。

## 持续的委托和当轮的权限

例如，「按标准第 2 版退回缺少出处的内部纪要」可以作为带期限和适用对象的工作区委托。新会话接手后，An 用当前 task、turn、主体、材料和策略核对此委托。符合条件时可以沿用这条规则，并在动作回执中记下实际使用的版本。旧会话获准导出一次的许可仅在原范围内有效。撤销长期委托或更换策略后，尚未执行的受保护动作须重新核对，已交接的版本与当时的授权事实仍可追查。

## 现有基础与首版验收

仓库已支持 harness/session 绑定、同一绑定重连到当前任务、按 workspace 列出已发布交付，以及从图交付创建新任务。现有 `an_handoff` 把候选版本定向交给指定 spool。这里设计的「交给主 agent」另有持久收件、用途和审阅状态。[工作区绑定](workspaces.md) · [任务与图交付恢复](../src/workspace.rs) · [现有交接权限](permissions.md)

已有来源查询可以按权限核查交付的上游证据，任务关闭后已有文件版本回收。首版要补齐主 agent 收件、跨会话接续与接管、指定时点的只读快照，以及这些新增引用的保留规则。已有工作区交付沿用原 ID 和发布记录。[来源查询](../src/graph/sources.rs) · [版本回收](../src/store/gc.rs)

| 无头验收场景 | 预期结果 |
| --- | --- |
| 容器产生三份草案和日志，只交回一条待审提议，主 agent 离线期间宿主重启 | 重连后同一产物 ID、版本和交接回执只出现一次，状态仍为待审。草案和日志的标题、内容均未出现在工作台。 |
| 主 agent 要求补证，随后采用新版，并尝试只凭审阅交接对外导出 | 两次处理分别指向各自版本。收件和采用可查，业务提议仍待确认，导出被拒绝且没有成功发布或导出的回执。 |
| 两个会话在同一 workspace 操作不同任务，再由另一会话接续第一项未关闭任务 | 两份任务上下文独立。仅提供 session ID 无法接续，经授权接续后仍是原任务和原收件。主 agent 接管生效后，旧主体的新写入被拒绝。 |
| 更换 turn，再撤销工作区长期委托 | 旧凭据和一次性许可失效。有效的长期规则可在新 turn 核对后使用，撤销后无法再据此退回纪要。旧回执仍能定位当时的委托版本。 |
| 给 subagent 一份只含第七段的快照，随后追加图节点并重试原节点 | subagent 只能读到获准版本，修改快照被拒绝。两次读取的字节和尝试 ID 一致。报告作为新产物交回，原始录音及新尝试保持不可见。 |
| 关闭任务并回收文件，再在新任务打开交付和引用证据 | 交付与被引用的第七段保持原版本，仍可经授权读取。未引用的临时试稿可以回收。只有发布记录的历史交付按原记录列出。 |

### 已验收：离线交回与主会话重连

创建工作区时可带 `--harness H --session S`（或稳定的 `--key K`）登记主 agent 的唯一绑定。未指定时沿用原工作区行为。主会话的活动任务控制器可签发 `{"right":"read_inbox"}`；客户端用该凭据连接原 MCP 会话绑定，调用 `an_provenance` 的 `inbox` 获取待审正文与回执。宿主每次读取都核对当前绑定和凭据。会话标识单独不足以读取收件。

首版交回一个文本块。来源任务先登记产物版本，然后让控制器通过 `grant` 对本任务签发 `{"right":"submit_review","source":{"artifact":"schedule","version":1,"block":"proposal"}}`。限制 workspace 流向时，要放行 `["submit_review", 块端点, workspace ID]`。宿主在签发时检查流向及宿主策略，实际交回时再次检查委托的有效范围。受托方通过 `submit-review` 提交 `source` 和 `idempotency_key`；回执固定用途为审阅、收件角色为主 agent，并标明来源任务、登记游标与已有的生产尝试。主工作台只投影选中块的正文。文档其余内容和来源证据沿用各自的读取权限。

验收使用 `an-minutes-organize:provenance` 本地镜像，运行 `python3 tests/workspace_inbox.py`。真实容器写出三份草案、一份包含公开提议与私有备注的文档，并输出日志。主 MCP 离线时交回提议，来源任务关闭并回收后，重新启动主 MCP 两次均可核对原收件及其处置。已创建但没有主绑定的旧工作区暂未提供补登记流程。主会话接管属于后续验收。

主会话控制器可单独签发 `{"right":"review_inbox"}`。使用 `review-inbox` 提交 `receipt`、`idempotency_key` 和 `outcome`（`adopt`、`return` 或 `request_evidence`）。每条收件只处置一次，相同请求可安全重放。列表保留原始交接回执，并在已处理项上附加 `disposition`。补证后的新版通过新的交接进入收件箱。业务决定与发布继续按各自的授权办理。
