# 产物流设计（八）——自然交互与 An 的模型职责

**首版无需给 An 配置常驻 LLM。** 工作区的主 agent 理解用户的自然语言，负责澄清、起草和解释。An 保存用户原话和当时选中的对象，依据授权、版本和回执展示进展。即使主 agent 离线，用户也应能打开工作区、核查来源、取回已发布交付，或直接停止任务。

## 用户说「改这段，发给客户」

用户在纪要第 3 版选中第七段「周五上线」，输入「把这段改得稳妥一点，发给客户」。这句话可以先产生一份有用的草案，发送则要等到具体版本、接收方和授权都明确。

1. **固定用户所指的对象。** An 根据可信绑定确认工作区、任务和轮次。宏 UI 随原话附上用户所见的图修订和事件游标，以及所选产物 ID、版本和块 ID。界面上已选定客户，就附上接收方引用。只有「客户」两个字时，接收方留空。An 校验这些引用是否属于用户可见的对象，记下接收指令时的图位置，并在把上下文交给主 agent 前核对它的权限。即使第 4 版已经改写这一段，原选区仍打开第 3 版，并标明已有新版。无头客户端可直接提交同样的引用。[产物版本与块引用](artifact-revisions.zh-CN.md)
2. **把改写交给主 agent。** 主 agent 核查获准的原文，发现负责人当时只说了「建议周五」。它可以提出「建议于周五上线，日期待负责人确认」，交回带差异的新草案，引用所改段落和依据。用户能看到改了哪句话。批准上线要由有权主体另行署名。[决定与验收的职责](decision-authority.zh-CN.md)
3. **按实际对象交接。** 接收方尚未确定，就请用户选定客户。已有委托和流向策略覆盖这版草案、实际接收方和发送用途时，An 可以执行并留回执。需要额外授权时，只呈现尚待确认的动作。若策略禁止外发，则保留草案并记录拒绝。工作区按回执分别显示草案已生成、已交给发送工具或接收方已确认。发送后失去回执时显示「结果未知」，重开页面只核对原调用。[身份、授权与权限传递](material-permissions.zh-CN.md)

## 用户问「这段是怎么来的」

在产物页选中这段文字，默认先展示获准查看的来源块、实际经过的 spool 与节点尝试，以及作决定时的图。有决定回执时，还能看到谁在何时确认了哪一版，以及当时的授权依据。「查看来源」可以展开原文、当次输入、留存的日志和交接回执。执行记录能证明整理 spool 收到过哪版纪要，报告里的块引用说明作者用哪句话作依据。旧交付只记录到文件时，就展示该文件和版本。标题、引用关系和正文都按查看者当前的权限呈现。[决定的来源与影响](artifact-flow.zh-CN.md)

同一处提供「请 agent 解释」。用户也可以在指令框用自己的话追问。主 agent 的回答关联原指令，注明作者，并可回到所引证据。如果工作区要保留或引用这份解释，就把它作为独立产物保存，记录作者、来源块和当时的图位置。解释可以修订，每一版都能查到自己的依据。

任务需要摘要、翻译或对照材料时，主 agent 可以在图上追加模型节点。An 在发送前核对获准模型、输入版本和预算，记录尝试、输出版本及后端报告的用量。预算耗尽时，这一步显示失败原因。已发出而无法确认结果的调用保留为「结果未知」。两种情况下，已有的来源和回执仍可打开。主 agent 在 harness 中怎样组织推理，由 harness 负责。[宿主模型调用](graph-studio.md#host-model-calls)

## 动态图与用户控制

任务页显示正在展开的流程，产物页默认定位到生成所选版本的路径。例中的报告指出「建议」与「已确认」有出入，主 agent 可以通过任务 MCP 追加「请负责人确认」。An 校验变更、调度获准的节点，分别记录提议、实际执行和被替代的步骤。回到旧决定时，用图修订还原当时的节点和边，用截止游标还原当时的执行、等待和交接。后来追加的确认步骤出现在较晚的图中。容器内试过的几种措辞可留作运行日志，需要独立委派、授权或交付的一步再进入图。[Agent 如何接入 An](agent-access.zh-CN.md)

时间线展示指令、agent 回复、阶段进展、决定、交付、失败和控制。即使 agent 留言「已发送」，发送状态仍取自实际回执。主 agent 离线时，有效任务和轮次内的自由文本可以先保存，显示「已记录，等待处理」。harness 恢复后按游标接续。回答某个待决问题要提交该请求的正式响应。暂停、停止和撤权经可信控制器直接执行，停止意图和终止结果各有记录。查看私有材料始终需要当前有效的读取权。[工作区与只读执行快照](workspace-lifecycle.zh-CN.md)

## 现有基础与首版验收

当前 Studio 随指令提交原文和屏幕上的图修订，宿主已记录所见修订、接收时修订和过期标记。宿主按事件生成时间线，已能查询节点或交付的上游执行，并对证据正文单独核权。现有模型节点可按任务授权、计量和恢复。[Studio 指令入口](../studio/orchestrator/macro/graph/graph.js) · [指令、时间线与控制](../src/graph/host.rs) · [来源与证据查询](../src/graph/sources.rs) · [模型调用记录](../src/graph/model.rs)

首版还要把选区、接收方和用户所见的事件游标随指令固定下来，在产物页接通块级来源、历史图和可引用的解释版本。以下场景用无头客户端和可计数的模型、发送工具验收。

| 场景 | 可核对的结果 |
| --- | --- |
| 关闭主 agent 和模型，保留用户的有效授权，从工作区打开交付并查看一段话的来源 | 取回文件的 SHA-256 与发布时记录的一致，能查到获准的来源块、spool 和只读执行快照。模型调用为零。撤回私有证据的读取权后，再次查询只返回当前可见的记录。 |
| 在第 3 版选中第七段并提交指令，主 agent 接手前第 4 版已将该段拆分 | 原话、原块和用户所见图位置均可重开，An 接收指令时的图位置也可查。改写能追溯到第 3 版，采用第 4 版需要显式选择。 |
| 主 agent 离线时，在已有待决请求的指令框输入「同意，发吧」，再用宿主控制停止任务 | 自由文本留下指令回执，待决请求没有因此获得正式响应或发送许可。停止立即登记，终止按观察结果结清。恢复后能找到原指令和已停止状态。 |
| 审阅后追加「请负责人确认」，在同一图修订下先等待、后得到答复，再重启宿主 | 当前图包含新增步骤，审阅时的旧快照保留原路径。新增步骤在答复前的游标显示待答，在答复后的游标显示已答，均能定位到当时的材料版本。 |
| 为同一段材料请求解释，分别使用获准的模型节点和已耗尽的预算 | 成功的解释可保存并被另一份文档引用，能回到作者、来源版本和模型调用。预算耗尽时新增发送次数为零，解释步骤显示失败，来源记录仍可查。 |
| 草案已完成，先留空客户，再指定有发送授权的接收方，并在发送后丢失回执 | 客户未定时发送次数为零。授权覆盖后只调用一次发送工具，保留实际版本和接收方。重新打开仍显示结果未知，客户收讫须有相应回执。 |
