# 产物流设计（三）——人、agent 与 An 怎样分工

一份纪要写着「周五上线」。审阅 agent 可以判断这句话是否忠实于会议原文。排期负责人可以决定是否周五上线。编辑负责人可以授权把核验通过的纪要发到内部工作区。这三件事各有对象和后果，即使由同一主体完成，也应分别留下记录。

人确定目标和愿意委托的范围。agent 对专业判断署名，在明确委托内也可以成为实际的业务决策者。An 核对身份、授权和版本，保存决定，并记录自己实际执行了哪些动作。

## 谁对哪一步负责

| 工作 | 谁负责 | 可查的记录 |
| --- | --- | --- |
| 确定验收标准 | 人可以指定标准，也可以委托 agent 起草或选定标准 | 标准的具体版本、起草者、选定者，以及选定者的权限依据。 |
| 检验产物 | agent 在可读范围内核对来源并给出专业结论，例如证据充分、不足或冲突 | 验收者、所验的产物版本与块、标准版本、实际完成的检查、结果及证据。因权限或材料缺失而未检查的部分要标明。 |
| 登记已有决定 | 有登记权的 agent 可以依据会议原文和负责人的权限依据，录入已经作出的决定 | 分别记录原决定者、登记者、原文块、来源所载的决定时间与 An 的登记时间。界面注明「据会议记录登记」。原文只有建议时保留为提议，身份或授权依据缺失时标为待核实。 |
| 作出新的业务决定 | 有相应决策权的人，或取得该项委托的 agent | 记录实际决策者、授权者、委托版本、决定内容和生效时点。例如，agent 受托退回一份纪要时，决策者写 agent。 |
| 发布、更正或通知 | 获准的主体发起，An 在实际交接时检查版本、接收方和流向 | 分别记录谁授权、谁发起、哪版产物发往哪里，以及宿主观察到的结果或接收方回执。 |

同一个 agent 可以起草并核验一份文档，记录保留两个动作的署名。若标准要求独立复核，则按该版标准检查复核者身份。harness 如何分派 subagent 由 harness 管理。An 记录经验证的调用主体，harness 报告的参与者另行注明。

## 如何委托一个决定

以「编辑负责人委托审阅 agent 按标准第 2 版退回缺少出处的内部纪要」为例。委托生效时，An 保存一份以后仍可还原的记录。

- **谁授予谁。** 保存授权者、其可委托此项工作的依据，以及受托主体的可验证身份。agent 可以提出委托请求，由有权授予者确认。
- **可以决定什么。** 写明适用的工作区、任务或材料范围、允许的决定、条件、标准版本和有效期。例中的委托允许退回纪要。要替负责人改变上线日期，或把纪要发给客户，都需要覆盖相应事项的授权。
- **后续动作有什么条件。** 人也可以同时委托「核验通过后，发布这版纪要到内部工作区」。采用哪份核验结果、要发哪个版本、允许发给谁，须能在发布时逐项核对。workspace 和宿主流向规则继续生效。

收到 MCP 请求后，An 先从可信绑定取得调用身份，再核对该主体在此时有效的业务委托。决定引用委托版本，审计记录只保存非秘密标识。委托到期、撤回或被替换后，新决定按当前权限处理。委托不足时，agent 仍可在获准范围内提交意见，待有权主体确认。原有决定始终能查回作出时的授权。

长期委托如何归属工作区、换会话或 turn 后怎样接续工作，见[主 agent 的 Workspace](workspace-lifecycle.zh-CN.md)。

## 一次退回怎样落账

1. **先给出核验结论。** 审阅 agent 对照标准第 2 版，发现纪要第 3 版的「上线日期」块写的是「已确认」，而原始记录只写了「建议」。它提交署名的结论「证据不足」，同时固定两个块、标准和实际检查结果。An 校验引用和读取权限，业务判断由审阅者负责。
2. **记录谁作了决定。** 若该 agent 受托退回这类纪要，An 在同一事务里核对委托和受检版本，写入「退回纪要第 3 版」的决定与理由。决定指向实际决策者、委托版本、核验结论版本及当时的图修订和事件游标。发给起草人的通知请求随决定一起提交，提交后才执行。只有审阅权时，保存核验结论与退回建议，等待有权主体拍板。
3. **单独核实后果。** An 执行通知或发布前检查此动作的当前权限、目标和版本。已决定退回、已发起通知、对方已收到，是三个可以分别查询的事实。通知失败或发送后回执丢失时，动作分别记为失败或结果未知，退回决定仍然有效。
4. **恢复、更正和撤销。** 同一幂等键和相同内容返回原决定回执，复用该键改变内容时报告冲突。重启后按原请求标识核对动作回执。若需再次发送结果未知的通知，须显式重试并另记尝试。撤销委托后，仍需该委托且尚未发起的动作停在授权检查处。有权主体以后更正或撤回决定时，新增记录指回原决定，并能查出哪些接收方已收到旧版、哪些更正通知仍待送达。

核验结论与业务决定都是可以独立修订的产物。核验了纪要第 3 版，就能回查当时用的证据。第 4 版需要自己的核验记录。受托 agent 有权修订纪要时，可以纠正措辞，原始排期决定保留自己的版本历史。[产物版本与块引用](artifact-revisions.zh-CN.md) · [决定的来源与影响](artifact-flow.zh-CN.md)

## 人怎样确认，agent 怎样提交

宏 UI 和 CLI 应把动作及对象写在确认文字里，例如「确认纪要第 3 版准确」「批准周五上线」「发布纪要第 3 版到内部工作区」。一次确认可以覆盖明确列出的多项动作，An 分别记录其作用对象和授权。用户委托 agent 在范围内作决定后，agent 可以从任务 MCP 提交，宿主依据已验证的身份归属决定。超出范围时呈现需要确认的具体事项。

现有实现已经能签发绑定任务和 turn 代次的 agent 凭据、核对流向、记录人工面板响应，并在推进图前持久化幂等提交。首版设计在这些基础上补充业务委托、署名核验结论，以及决定与后续动作回执的关联。会议纪要的验收标准和业务措辞放在实验中，宿主使用通用的主体、范围、版本和回执。[现有权限机制](permissions.md) · [人工响应](../src/graph/host.rs) · [图提交](../src/graph.rs)

## 首版无头验收

| 场景 | 可检查的结果 |
| --- | --- |
| 有排期权的负责人在两份会议记录中分别明确批准周五上线、建议周五上线 | 第一份能查到来源所载的决策者和实际登记它的 agent。第二份保留为提议。两者均能打开获准读取的原文块。 |
| 同一个 agent 先仅获审阅权，再获有条件的退回权 | 前一次留下署名报告与建议。后一次的退回决定写明 agent 是决策者、编辑负责人是授权者，并可定位标准、纪要版本、块及缺失证据。 |
| 受托发布通过核验的内部版本，随后改用未核验的新版或改发客户 | 已核验版本在流向允许时一次发布成功。更换版本或目的地时，宿主挡住发布，已有核验结论保留原对象。 |
| 用一次人工响应确认纪要准确并批准将第 3 版发到内部工作区 | CLI 与 Studio 使用同一份动作清单。响应能查到两项确认及各自的对象，排期决定保持原有状态。实际发布另有回执。 |
| 在退回决定落账后重启，模拟通知失败、回执丢失，并重放决定请求 | 决定 ID 与回执保持一致。通知分别能查到失败或未知状态，恢复和重放均不会自行重发。 |
| 决定生效后撤回委托，再发起同类决定或执行仍需此委托的排队动作 | 两个新操作都受当前权限约束，旧决定仍显示当时有效的授权。有权主体更正时产生关联记录，旧决定及已发生的交接仍可查。 |
