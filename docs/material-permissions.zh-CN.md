# 产物流设计（六）——身份、授权与权限传递

主 agent 请 subagent 核对纪要里的一句「周五上线」。用户的一次确认可以写成「允许这次审阅读取纪要第 3 版第七段和核验标准第 2 版，把报告交回本工作区的主 agent，有效到任务结束」。An 在提供材料和交回报告时分别核对这项委托。读取原始录音需要额外授权，正式批准上线则需要有决策权的人或 agent 署名。

## 一份委托授予哪些权力

| 动作 | 授权必须说清楚什么 | 在本例中的结果 |
| --- | --- | --- |
| **读取材料** | 谁、为哪项委托、能取得哪些不可变版本。范围可以是整份执行快照，也可以只是指定尝试的输入、输出、证据片段或文档块。 | 审阅者可取得第七段和标准的固定版本，沿引用打开完整纪要或录音需要相应的读取权。 |
| **定向交回** | 哪项工作可用哪些来源形成结果、允许交回什么、接收方是谁。实际交接固定到具体的输出版本。 | 新报告进入主 agent 的待审收件。发布到工作区共享区、交给另一任务或导出给客户，分别核对该目的地的流向。 |
| **代表人作决定** | 谁授予哪位主体对什么事项作决定的权力、适用条件和期限。 | 审阅者可以署名报告「证据不足」。若要以此退回纪要或确认排期，需要覆盖该事项的业务委托。[决定与验收的职责](decision-authority.zh-CN.md) |

历史材料按版本只读。审阅者通过提交新报告给出结论，修订原产物还需要它的修订权限。An 在读取、交接和决定的边界上执行规则，harness 继续负责组织主 agent 和 subagent 的工作。

## 谁可以把权限交给谁

An 通过可信控制器、受限调用凭据或宿主绑定的执行尝试确定请求来自谁。工作区、任务、会话、实例和产物的 ID 用于定位记录。harness 提供的执行者标识可供追溯，权限取自 An 核验过的授权记录。共用主 agent 的调用通道时，An 能确认的调用者是主 agent。需要独立限权的 subagent 使用绑定到本次委派的受限入口，也可直接接收 An 准备的只读文件，在限定的出口交回报告。[Agent 如何接入 An](agent-access.zh-CN.md)

每份授权都记下谁依据什么权力，允许谁在什么工作区和任务中做哪件事，以及涉及的材料、接收方、期限和可再委托的范围。具有相应授予权的人或主 agent 可以转授。子授权引用上级授权的具体版本，材料、动作、目的地和有效期均受上级允许转授的范围约束。主 agent 有权读摘要时可以亲自核对，把这份摘要提供给 subagent 还需有权转授这次读取。harness 新建线程或复用旧实例时沿用同样的检查。[委派与执行者的归属](spool-execution.zh-CN.md)

工作区可以保存长期委托，每次使用仍核对当前主体、task、turn 代次以及工作区和宿主策略。明确禁止的流向在交出字节前被拒绝。允许申请但尚缺授权，或规则指定「逐项询问」时，返回待确认的具体请求。读取和交回可以由人一次批准，两项分别记录，后续按实际动作使用。[工作区与操作轮次](workspace-lifecycle.zh-CN.md)

## 只读核查怎样执行

1. **冻结并提供获准材料。** 执行快照归属原工作区和任务，固定图修订、事件截止游标、节点尝试及材料版本。本例交给审阅容器的只读目录只含第七段和已获准的标准。列表、搜索、预览和来源查询使用同一可见范围，私有文件名、摘要和引用关系也受保护。后来追加的节点和新的文档版本需要重新匹配授权。[产物版本与块引用](artifact-revisions.zh-CN.md)
2. **核对结果的去向。** An 核对实际报告版本、接收方和本次工作取得的受控材料，包括可读的旧工作副本。若后来又向审阅者提供了原始录音，原先仅覆盖第七段和标准的交回许可就不足以放行。报告省略录音引用或改名为「公开摘要」，已提供的材料清单仍包含录音。来源超出许可或无法确定时，暂停交回。在策略允许的范围内，有权主体可以单独核准这份冻结报告交给指定接收方。
3. **在实际动作前核对有效性。** 排队期间撤销上级授权，依赖它的子授权也失效。换 turn 后，旧轮次凭据和一次性许可失效，尚在期限内的长期委托可在新一轮核对后使用。挂载后发生撤销，已经交给运行的材料保留「已提供」记录。收回仍在使用的挂载，要等卸载或停止得到确认。尚未执行的交回按当前权限处理。

## 回执应当证明到哪一步

授权记录描述允许发生的动作。提供材料的回执记录授权依据、受托主体、委托、任务与尝试、实际交出的版本清单、范围和时间。整份快照只读挂载成功，能证明这些文件在该容器中可读。按块请求返回第七段，能证明 An 提供过第七段。报告引用第七段，则是作者对其依据的声明。容器内部没有观测到的阅读行为保持未知。

交回时，An 将接收方、报告版本、授权版本和交接回执与主 agent 的收件一并提交。重放相同的已完成交接返回原回执。失败、拒绝和待确认的请求分别记录。审计只引用非秘密标识。日后核查时，回执保留交接当时的授权依据，打开私有证据仍需查看者当前有权读取。[主 agent 的收件与只读执行快照](workspace-lifecycle.zh-CN.md)

## 现有基础与首版验收

现有 agent 凭据绑定任务和 turn 代次。An 已能核对工作区流向、宿主策略和意图卡，支持一次确认多条图内路线，也已有按尝试与类型单独申请证据的入口。按具体委派转授权限、按块提供快照、按实际来源和接收方核对报告交回，是首版待实现的能力。下面列出它们的验收条件。[现行权限操作](permissions.md) · [凭据与权限检查](../src/permission.rs) · [意图匹配](../src/intent.rs) · [证据读取](../src/graph/sources.rs)

| 无头验收场景 | 预期结果 |
| --- | --- |
| 一次批准读取第七段和标准，并允许交回主 agent | 容器输入只含所选材料。报告交回固定接收方，无须再次确认。授权、提供材料和收件各有记录。 |
| 主 agent 只有读取权时尝试转授，再由有权者准许它转授第七段 | 第一次派发在提供材料前被拒绝。第二次可以派发第七段，扩大到整份快照、延长期限或借用其他线程的授权均失败。 |
| 审阅者沿第七段的引用查录音，随后新增节点并重试原节点 | 从读取、搜索和来源查询均得不到未获准的录音及其名称。重读原快照仍得到原来的版本和尝试。 |
| 另外批准并向审阅者提供录音，保留原先的报告交回许可，再把带私有内容的报告改名后交回或导出 | 实际来源超出原交回范围，两个动作均未产生成功回执。只有在策略允许且新授权覆盖具体版本和接收方后，相应交接才能完成。 |
| 仅持读和交回权限，提交「证据不足」并试图确认上线 | 署名报告可进入主 agent 的待审收件。业务决定保持待确认。有明确决策委托的主体另行决定时，记录能指向该委托。 |
| 分别在挂载前、挂载后交回前、交回完成后撤销上级授权，再重启宿主 | 第一例没有材料提供回执。第二例保留已提供清单，凭原授权交回被拒绝。第三例保留原回执，重放同一交接只查到一份收件。 |
| 提供整份快照，报告只引用第七段 | 审计显示整份快照已提供，以及报告引用了第七段。未观察到的逐文件阅读情况保持未知。 |
