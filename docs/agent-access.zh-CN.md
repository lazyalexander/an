# 产物流设计（七）——Agent 如何接入 An

**任务范围的 MCP 是主 agent 操作 An 的唯一入口。** 一个工作区由一个主 agent 负责，它可以同时推进多个任务，每次调用都使用对应任务的接入配置。An 持有动态图、产物版本、权限和执行回执。harness 管理会话、线程和 subagent，决定下次唤醒谁。换一个 harness 接续工作时，仍可凭当前授权找回同一份材料和执行记录。[工作区、会话与任务](workspace-lifecycle.zh-CN.md)

## 谁需要连接 MCP

设主 agent 要核对纪要第 3 版第七段里的「周五上线」，报告只需交给本工作区的主 agent。

| 谁在做什么 | 怎样接入 | An 能确认什么 |
| --- | --- | --- |
| 主 agent 发起审阅 | 通过 An MCP 查获准的材料和 spool、提交工作、追踪状态、领取交回的报告。需要更多权限时提交申请。 | 哪个受托主体发起请求，An 接受了什么、实际提供了哪些版本，以及谁收到了报告。 |
| subagent 核对已选好的材料 | 默认给它第七段和核验标准的冻结版本、块引用及只读文件。它可以用普通文件工具比较，在约定的输出目录写报告，全程无需 MCP 连接。 | 哪次执行取得了哪些材料。若主 agent 代交报告，提交者记为主 agent，harness 提供的作者署名单独保存。 |
| subagent 需要独立查证、作决定或交接 | An 核验委托后，由 harness 把仅限这项工作的 An MCP 入口交给受托者。它可以申请指定证据或行使已授予的决定权。 | 受控读取、正式决定和对外交接都关联经验证的受托者或执行尝试、授权依据和实际结果。 |

控制器保管宿主凭据。harness 提供通用 shell 时，须将控制器文件、套接字和 An 数据库与 agent 隔离。主 agent 的 MCP 进程使用绑定任务和 turn 的 `AN_AGENT_TOKEN`。需要 An 验证署名的受托者使用自己的受限入口，共用主 agent 的通道只能确认主 agent 提交。[身份、授权与权限传递](material-permissions.zh-CN.md)

容器保持禁网，大文件经授权挂载，报告经输出端口交回。容器里的分阶段驱动可以写出 `subgraph.json` 来提议下一步。宿主核对这版提案能否公开到图上，检查扩展预算和新增节点，再为下一次执行提供获准的材料。[Spool 与执行尝试](spool-execution.zh-CN.md)

主 agent 调用已注册的下游 MCP 工具也经过 An。网关核对任务获准的工具、服务注册版本和本次调用参数，再通过本地 stdio 转发。涉及文件的桥接工具由 An 准备传输目录并收取结果。向下游发出请求后失去回执，An 保留「结果未知」，接续者先核对原调用。对外操作的重做需要显式选择。[下游网关](../src/mcp.rs) · [桥接与文件交接](bridge-artifacts.md)

## 中途退出后，动态图怎样接着走

1. **找到起点。** 用户发出核对指令，An 保存原话和指令事件。主 agent 调用 `an_graph_state`，取得当前图修订、节点尝试，以及本轮意图卡上哪些流向已获批准。图修订指明准备在哪一版图上修改，事件游标标识已经看到哪条事件。`after` 只筛选后续事件，返回的图仍是当前图。要核查决定当时的材料，则打开固定了图修订、截止游标和材料版本的执行快照。[决定当时的图与证据](artifact-flow.zh-CN.md)
2. **先提交能确定的工作。** 主 agent 用 `an_graph_submit` 追加核对步骤，给出 `base_revision` 和 `idempotency_key`，可用 `instruction_cursor` 关联用户的指令。An 提交图变更后返回修订和游标。即使在收到回执前断开，重连后用原键和原参数重发也能取回同一回执。节点是否已运行、报告是否交回，各查相应的执行或收件记录。
3. **根据结果追加一步。** 报告指出原文只有「建议周五」。主 agent 此时才追加「请负责人确认」，引用这版报告。如果期间另一条分支已改变图，新提交收到 `conflict`。主 agent 读取最新修订及事件，重新判断是否还需要提问。尚在排队的旧步骤可以被替代，已经发生的执行保留原尝试和版本。
4. **等待答复和重连。** 主 agent 可以在等待答复时退出。用户回答后，An 持久保存事件，控制器把任务、触发事件、游标和任务 MCP 配置交给 harness。harness 可恢复原线程，也可启动新进程。接续者按已处理的游标补读事件，核对原尝试和收件，再决定下一次提交。已换 turn 时先取得本轮凭据，沿用旧材料仍须有当前读取权。[图接口与回执](graph-studio.md#agent-contract) · [控制器唤醒约定](../studio/an_host/runner.py)

暂停、停止和撤权由人通过可信控制器直接执行，agent 离线也能生效。停止请求和实际终止分别记录。唤醒只通知 harness 有事可处理。确认进程未启动时，控制器可以重试唤醒。进程已经启动而结果未知时，接续者根据任务记录判断工作进度。普通协作由 harness 留痕，容器内的试算可通过该次运行实际留存的文件或日志核查。

用户在主 agent 离线时可以核查哪些事实、何时需要 agent 解释，以及指令怎样指向当时选中的文档块，见[自然交互与 An 的模型职责](natural-interaction.zh-CN.md)。

## 现有入口与首版无头验收

仓库已有任务级 MCP、增量图提交与查询、权限范围提议、向用户发送消息，以及带游标的 harness 唤醒。现有 `an_graph_state` 返回当前任务图，`an_deliveries` 列出已发布交付，`an_handoff` 的接收方是指定 spool。[现有工具清单](../src/tools.json) · [图提交与重放](../src/graph.rs) · [任务凭据签发](../studio/an_host/controller.py)

首版还要补齐按委托限制的审阅入口。领取快照时，返回指定图修订和事件游标下获准的尝试、版本和块，状态查询也遵守同一可见范围。交回报告时，绑定委托、被核查的版本、引用的块、报告版本和接收方。主 agent 可以按委托查回同一份收件和回执。

| 无头验收场景 | 预期结果 |
| --- | --- |
| 主 agent 只接 An MCP，在提交核对后丢失回执时退出一次，在等待人答复时再退出一次。两次均由 harness 启动新进程接续 | 重发相同请求取得原回执，核对只派发一次。第二次接续能按游标找到答复，查到原尝试、材料版本和当前授权，最终只产生一份收件。 |
| 两个提交引用同一条指令、基于同一图修订，第一份已追加确认步骤 | 第二份得到修订冲突。重新读图能看到第一份提交及其指令来源，接续者可以沿用已有步骤。 |
| 两份只读材料交给无网络、无 MCP 凭据的审阅容器，主 agent 代交结果 | 容器可完成比较并产出带块引用的报告。收件指向实际材料版本和执行尝试，提交者与 harness 声明的作者分别可查。 |
| 受托者持有第七段的读取权和有条件的退回权，尝试读完整录音，再对纪要行使退回权 | 原始录音及其私有元数据保持受限，受托者无法批准自己的申请。满足委托条件后，退回记录能定位到实际决策者和授权版本。 |
| 主 agent 离线时暂停任务、停止未结工作并结束 turn，再用旧凭据重连 | 暂停期间不派发新工作。停止意图可查，终止得到确认后才记为已取消。旧凭据无法继续受保护操作。 |
| 下游工具已收到请求，但在返回结果前断开 | 状态保留原调用及未知结果。重新连接或再次唤醒后，下游实际收到的调用次数仍为一次。 |
